## About the 38 failures

Every one is the 8B model on your Mac:
- not calling a tool it needed (PPL and PAY changes most often)
- asking for an id instead of looking it up
- picking the wrong loan when a borrower has two
- guessing instead of asking
- getting a sum or a label wrong

Where the code could take a step away from the model, it now does. The server works out dates, finds people
by name, runs the loan checks, checks amounts and people against your words, and drops options nobody asked
for. Each of those took failures off the list, from 99 down to 38. The last rounds moved only a few each time,
which shows the model itself is now the limit. Your live chat uses Groq's larger models, which scored 20 of 20
on your real questions.

None of these failures saved anything wrong. Wrong cards were shown in a few, but the card showed the
wrong loan or amount for you to see, and none were confirmed.

## What was fixed

The 12 bugs from the first review:

1. Pending requests by dates sent the wrong option name, so the app refused them.
2. The rules file said proof of payment is optional. The app requires it now, so the rules file was updated.
3. `npm run db:seed` didn't clear demo pending requests.
4. An older card could still be confirmed. A newer card now marks it "Replaced".
5. An edit card could drop the lenders, and the app refused after Confirm.
6. "Extend, interest paid now" didn't require the screenshot on the card.
7. Payment, proof and extension ids weren't checked, so a made-up id still got a card.
8. A bad amount or date still produced a card.
9. Misspelled borrower names led to offering a duplicate person. Added "did you mean", and a card warning when
   a "new" person looks like someone already on the list.
10. An unclear lender name was guessed. The AI now asks.
11. "Today" was in UTC. It's Manila time now.
12. A rate typed as "7%" showed as "7%%", and long chats dropped their first message.

Found by the test runs and fixed:

- **Action search:** it matched parts of words, so "mark as good" found "add a note" via "re**mark**". It now
  matches whole words only.
- **Dates:** the server works out "today", "tomorrow" and "4 weeks". Weeks always decide the due date, so the
  model never counts days.
- **Names instead of ids:** the AI may write a person's name where an id belongs. The server finds them, or
  refuses when two people fit. A made-up id is still refused.
- **Loan checks before the card:** the loan form's own checks run before a card appears. Whole weeks, due after
  start, more than ₱0, and lenders adding up to the amount exactly.
- **Edits:** an edit starts from the loan as saved, so the AI only sends what changes.
- **Unasked loan options:** weekly interest, fixed amount, rates, admin cut and reminders are dropped unless the
  Admin's own words mention them. One demo loan was saved with weekly interest nobody asked for, before this fix.
- **Overview:** now names who is overdue (with days late) and includes "Due this week". That figure is back on
  your dashboard, and back in the rules file.
- **Loan search:** "dans" finds Dan, and an unknown name offers "did you mean".
- **Borrowers:** a deleted borrower gets a "restore?" hint instead of being treated as new. Surnames shared with
  a lender ("Cruz") are mentioned.
- **Nudges:** one correction per question when the model replies empty, only says "let me check", or answers a
  rules question without reading the rules. They cost nothing when the model behaves.
- **Ids:** they're removed from anything the Admin reads.
- **Long messages:** a message over 600 characters keeps its start and its end, where the question usually is.
- **Photos:** removing a photo that isn't there is refused before a card appears.
- **Rules file:** added loan extensions, "Remind me every N weeks" and "Due this week". These are new on `main`.
- **Fake image files (app-wide):** a text file renamed "receipt.png" used to be accepted as proof, in the app's
  normal forms as well as the chat. Every upload now checks the file's first bytes against its type before anything
  is stored (`src/lib/proof.ts`, `src/server/payments/uploads.ts`). Real JPEG, PNG, WebP, HEIC and PDF files pass.
  This changes the app's shared upload code, so try one real upload on the testing link.
- **Grounding against the Admin's own words:** before a card is shown, the server refuses
  - an amount the Admin never said ("20k", "twenty thousand" and "10k each" all count as said),
  - a borrower or lender the Admin never named (an edit only checks the people it adds),
  - a new loan or request with no length.

  The AI has to ask instead of guess. Funding a pending request counts the request's own amount and length.
- **More nudges:** "ready to confirm" or "here is the card" when no card exists, invented "did you mean" names, and a
  change request answered without trying the change. Up to two per question. If the model still claims a card,
  the Admin sees "I could not make the card for that" instead.
- **Extensions:** a typed "extra interest" is dropped on weekly-rate loans, where the app works it out itself.
- **Planning for the model:** when a message is a change request, the server looks up the fitting actions itself and hands
  them to the model before its first reply. Smaller models often forgot that step.
- **Exact names:** a "new" borrower whose full name exactly matches someone already on the list is that person.
- **Local AI switch:** `ASSISTANT_LOCAL_MODEL` in `.env.local` runs the chat on Ollama for free testing.
  It's ignored on Vercel. Groq stays the default.

## Changes saved during testing (demo account only)

- **SAFE-13, round 2:** the setup asked the AI to add a note. The model proposed "mark the loan paid" instead,
  and the test runner confirmed that card blindly. That was a runner flaw: a person would have seen the wrong
  title. Setup steps are now done exactly, never through an AI card.
- **LOAN-01, round 3:** a loan was saved with weekly interest nobody asked for. The card showed it, but the runner
  confirmed it. The server now drops unasked loan options, and LOAN-01 passes.

Every other confirmed change saved exactly what was asked. The demo data was reset at the end.
